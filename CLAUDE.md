# Instructions for Claude Code - FairAssess NJ

## What this project is
FairAssess NJ tests whether New Jersey towns over-assess lower-priced homes compared with expensive ones, using public MOD-IV parcel data, SR-1A sales, IAAO ratio-study measures (COD, PRD, PRB), and Chapter 123 range checks. It also runs a free website with a homeowner tax-appeal checker. The full plan is in private/gameplan.md. Read it when a task needs project context.

## Who you are working with
Zaden, a high school student. Explain things in simple words. When you give him commands to run himself, write them for Windows PowerShell.

## Folder map
- data/raw/ - untouched downloads. NEVER edit, move, or delete anything here.
- data/interim/ - cleaned and merged tables (not uploaded to GitHub).
- data/processed/ - final tables for analysis and the site.
- data/reference/ - Director's Ratios, tax rates, revaluation years, non-usable sale codes.
- notebooks/ - exploratory notebooks, numbered 01_, 02_, ...
- src/ - Python pipeline.
- reports/ - memos and one-page town findings.
- site/ - Next.js website. Vercel builds and deploys ONLY this folder.
- site/public/data/ - generated by src/export_site.py. Never hand-edit.
- site/content/ - Markdown for the appeals guide, methodology, and about pages.
- docs/ - methodology, data dictionary, changelog, work log.
- private/ - Zaden's private files. Never copy text from here into other files unless he asks.

## Rules
1. Do not run git commit or git push. Zaden reviews and commits every change himself.
2. Never put passwords, API keys, owner names, or home addresses in any file outside private/.
3. Every website page must show: "FairAssess NJ provides public-data analysis for educational purposes. It is not legal advice, tax advice, or an appraisal. Homeowners file and present their own appeals. Check your county board for current deadlines, fees, and forms."
4. Website writing: eighth-grade reading level, short sentences, numbers before adjectives. Never say "you will win." Always show the appeal deadline and fee wherever appeals are discussed.
5. Before saying a website change is finished, run npm run build inside site/ and fix any errors.
6. Keep Python simple: pandas, small functions, a short docstring on each one.
7. Add a dated line to docs/changelog.md for each meaningful change.
8. When you finish a task, list every file you changed.
